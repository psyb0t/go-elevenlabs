# go-elevenlabs

Unofficial Go client for the ElevenLabs REST API, generated with oapi-codegen. If you only want to use the client from an agent, read [.agents/skills/go-elevenlabs/SKILL.md](.agents/skills/go-elevenlabs/SKILL.md) instead; this file is about changing the code.

## Architecture

Generation pipeline, declared in `gen.go` and run by `make generate`:

1. `scripts/fetch-spec.sh` downloads `https://api.elevenlabs.io/openapi.json` to `api/openapi.json`.
2. `scripts/patch-spec.sh` writes `api/openapi.patched.json`: drops the `oneOf` from schemas that carry both `anyOf` and `oneOf` over the same members, and adds a `Schema` suffix to component schemas named like an operation's generated params type, rewriting every `$ref` to them.
3. oapi-codegen runs with `config.yaml` on the patched spec.
4. The result is `client.gen.go`: models, `Client` and `ClientWithResponses` in package `elevenlabs`.

## Stack

- Go 1.26.9, one package at the module root.
- oapi-codegen v2 and golangci-lint as `go tool` dependencies.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `client.gen.go`: generated client and models.
- `gen.go`: package doc and the `go:generate` steps.
- `config.yaml`: oapi-codegen config.
- `client_test.go`, `example_test.go`: tests against an `httptest` server, and the README example.
- `scripts/`: spec fetch and patch, lint and security scan scripts.
- `api/`: downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec, patch it, regenerate client.gen.go
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- `make generate` always downloads the current upstream spec, so a regeneration can pull in unrelated upstream changes. Review the `client.gen.go` diff before committing.
- Upstream spec problems come back on every download, and a new duplicate union or name collision fails the build. Fix them in `scripts/patch-spec.sh`, never in `client.gen.go`.
- Most `...Params` structs carry an `XiApiKey` field from the spec. Request editors run after params, so the client-wide auth editor wins.
- Audio endpoints have no `JSON200`; their payload is in `Body`.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
